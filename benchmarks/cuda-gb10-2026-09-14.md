# NVIDIA GB10 CUDA validation — 2026-09-14

Omawake was built on `promaxgb10-d666` (Linux aarch64, NVIDIA GB10, CUDA
13.0.88, driver 580.173.02) with the pinned CUDA builder and
`OMA_CUDA_ARCHITECTURES=121`. Tests used the catalog's full-FP32 CUDA encoder,
decoder, and joiner. Audio entered through `test --audio` and `benchmark`; no
microphone or speakers were used.

## Placement and accuracy

The cold file test reported `effective_runtime="cuda"`,
`fallback_used=false`, and detected `light-up` in `test_wavs/0.wav`. The second
fixture detected `lovely-child` and `forever`. Five measured iterations per
file produced the same detections on CUDA and default CPU (10/10 parity).

ONNX Runtime profiles recorded 78,016 CUDA provider node events for the
encoder, 5,088 for the decoder, and 1,272 for the joiner. `nvidia-smi pmon`
observed the Omawake process using 314 MiB and up to 13% SM. This proves that
all three KWS graphs reached the GB10 rather than merely accepting a CUDA
configuration.

The CUDA timing run was materially contended: an SGLang process occupied
82–95% SM and about 78 GiB throughout the sample. The timings therefore show
correctness under contention and are not an isolated GB10 performance
baseline. CPU used 63.6 MiB RSS in the cold test; CUDA used about 1.09 GiB.

Raw evidence from the validation host was written under `/tmp/omawake-demo`,
including benchmark JSON, provider configs, ORT profiles, and `nvidia-smi`
logs.
