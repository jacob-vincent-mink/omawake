# NVIDIA GB10 CUDA validation — 2026-09-14

The current runtime-neutral Omawake executable was validated on
`promaxgb10-d666` (Linux aarch64, NVIDIA GB10, driver 580.173.02). The external
stack used ONNX Runtime 1.29.0, its CUDA provider, CUDA 13.0 vendor libraries,
cuDNN 9.26, and the patched sherpa-onnx 1.13.8 adapter. Setup previewed and
probed those user-supplied libraries before an explicit apply. They are not
part of the default CPU release runtime.

The catalog's full-FP32 CUDA encoder, decoder, and joiner were used for the
like-for-like CPU comparison. Audio entered through the file benchmark path;
no microphone or speakers were used.

## Runtime, placement, and detection parity

The setup preview reported `applied=false`, then the explicit apply reported
`applied=true`. Both probes registered the CUDA provider and selected the GPU.
All CUDA runs reported `effective_runtime="cuda"` and `fallback_used=false`.

Nsight Systems captured 77 CUDA kernel summary rows from the Omawake process.
The leading convolution kernel ran 33,973 times; the trace also contains
ONNX Runtime CUDA elementwise/slice kernels, cuDNN convolution, cuBLAS, and
CUTLASS GEMM work. `nvidia-smi pmon` independently observed Omawake using up to
28% SM and 314 MiB of framebuffer memory.

Both CPU FP32 and CUDA produced the same detections on every iteration:

| Fixture | Expected and observed detections | CPU runs | CUDA runs |
| --- | --- | ---: | ---: |
| `test_wavs/0.wav` | `light-up` | 11/11 | 11/11 |
| `test_wavs/1.wav` | `lovely-child`, `forever` | 11/11 | 11/11 |

That is 22/22 file-level parity comparisons with no missed or added wake-word
detections.

## Cold and hot timing

Cold rows use a new process and one measured iteration per fixture. Hot rows
use a new process, two warmups, and ten measured iterations per fixture.

| Runtime | Load | Fixture | Cold | Hot p50 | Hot p95 | Hot p50 RTF |
| --- | ---: | --- | ---: | ---: | ---: | ---: |
| Default CPU, FP32 | 278.13 ms | `0.wav` | 73.60 ms | 69.82 ms | 70.06 ms | 0.01054 |
| Default CPU, FP32 | 278.13 ms | `1.wav` | 175.81 ms | 175.50 ms | 175.79 ms | 0.01050 |
| CUDA GPU, FP32 | 1,997.36 ms | `0.wav` | 2,086.07 ms | 2,461.60 ms | 2,985.16 ms | 0.37156 |
| CUDA GPU, FP32 | 1,997.36 ms | `1.wav` | 463.71 ms | 481.65 ms | 489.13 ms | 0.02882 |

The host was materially contended: an SGLang process occupied about 78 GiB of
GPU memory throughout the run. These timing figures demonstrate correct CUDA
operation under contention; they are not an isolated GB10 performance
baseline. The detection parity and process-specific Nsight trace remain valid
under that contention.
