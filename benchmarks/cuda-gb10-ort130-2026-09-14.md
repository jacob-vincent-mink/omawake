# NVIDIA GB10 CUDA Plugin EP validation — 2026-09-14

Omawake commit `f03fa53` was built on `promaxgb10-d666`, a Linux aarch64
NVIDIA GB10 host, and tested with the official ONNX Runtime 1.30.0 core and
standalone CUDA Plugin EP 0.1.0. Audio entered through the WAV file path; no
microphone or speaker was used.

The tested binary had SHA-256
`68fc50ded2e126e98b23ba530f819c4e1d805df6db8ba0686db2388d86c22283`.
The ORT core DSO had SHA-256
`64e903a43a041240fd6bcffe0ac6d4fea47ef87bf24b9d097801bd00a9612a4b`,
and the CUDA provider DSO had SHA-256
`84523bae764a3e6c1b1d82f9637ae1fa5a8be47f187828540aba96569259c092`.

Both publisher WAV fixtures matched the default CPU labels and timestamps
exactly. `0.wav` produced `light-up` at 3.00, 3.04, 3.08, and 3.16 seconds.
`1.wav` produced `lovely-child` at 5.36, 5.56, 5.84, 6.00, and 6.04 seconds,
then `forever` at 10.88, 10.96, and 11.00 seconds. Both runs reported
`effective_runtime="cuda"` and `fallback_used=false`.

CUDA compilation may retain CPU shape-helper nodes required by the provider;
that is provider graph partitioning, rather than Omawake's backend fallback.
The selected CUDA kernels performed the model work. `nvidia-smi dmon` observed
95–96% SM use throughout the captured `0.wav` run.

The first captured CUDA run loaded the model in 2.385 seconds. A later hot
driver/cache invocation loaded it in 453 milliseconds and processed `1.wav` in
2.82 seconds wall time. For comparison, the same direct implementation loaded
on default CPU in about 164–169 milliseconds; hot inference took about 58.7
milliseconds for `0.wav` and 147 milliseconds for `1.wav`.

Exact detector JSON and GPU telemetry are retained in
`cuda-gb10-ort130-results-2026-09-14/`. Earlier reports in this repository
cover the superseded sherpa adapter and ORT 1.29 provider path.
