# NVIDIA GB10 CUDA Plugin EP validation — 2026-09-15

Omawake commit `538d4191f28919fa2d0f6f6ec398a43b685584ce` was built from
its exact Git archive on `promaxgb10-d666`, an aarch64 NVIDIA GB10 host with
driver 580.173.02. The validation used the official ONNX Runtime 1.30.0 core
and CUDA Plugin EP 0.1.0. Audio entered through the publisher WAV fixtures;
the test did not open a microphone or play audio.

Every CPU and CUDA iteration produced the same wake-word IDs:

- `0.wav`: `light-up`
- `1.wav`: `lovely-child`, then `forever`

CUDA runs reported `effective_runtime="cuda"` and `fallback_used=false`.
`nvidia-smi dmon` recorded seven active samples during the hot run and peaked
at 44% SM utilization. These observations establish that the CUDA provider
executed the workload rather than Omawake's explicit CPU fallback.

Cold is a fresh process with no warmup and one measured iteration. Hot is a
fresh process with one warmup and five measured iterations. The machine's
driver cache had been used by earlier development validation, so cold here
means process-cold rather than reboot-cold.

| Lane | Load | `0.wav` | `1.wav` |
|---|---:|---:|---:|
| default CPU cold | 200.425 ms | 98.947 ms | 198.832 ms |
| default CPU hot p50 | 192.389 ms | 76.804 ms | 194.533 ms |
| CUDA cold | 452.139 ms | 636.058 ms | 662.441 ms |
| CUDA hot p50 | 467.725 ms | 268.420 ms | 674.982 ms |

CUDA is slower than CPU for this small streaming model on the GB10. Provider
dispatch and device transfers dominate the amount of graph work, so CUDA is a
functional option rather than the recommended performance choice for this
model.
